## Overview

REST memodelkan resource yang diidentifikasi URL. Gunakan HTTP method sesuai semantiknya dan hindari menyimpan konteks percakapan tersembunyi pada server.

## Concept

Fokus penerapan **REST API Fundamentals** adalah gunakan nama resource jamak. Pisahkan representasi dan storage. Dokumentasikan method dan status. Contoh berikut memperlihatkan konteks kategori REST API; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

## Implementation

1. Gunakan nama resource jamak.
2. Pisahkan representasi dan storage.
3. Dokumentasikan method dan status.

### Contoh terfokus

Periksa dependensi dan konteks pada komentar kode. Adapter seperti repository, provider, atau prisma diberikan oleh composition root; fragmen bukan server terpisah. Untuk contoh utuh, lihat [Complete Backend Starter](/docs/projects/complete-backend-starter).

```http title="rest-api-fundamentals.http"
GET /api/notes HTTP/1.1
Host: localhost:4000
Accept: application/json
Authorization: Bearer <access-token>
```

### Konteks kategori

```bash title="terminal"
curl -i http://localhost:4000/health
# HTTP 200

```

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk REST API Fundamentals, verifikasi langkah “Gunakan nama resource jamak” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

## Testing

Uji REST API Fundamentals dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “gunakan nama resource jamak” sesuai kontrak. Tambahkan test tanpa token dan test akses lintas user.

```bash title="verifikasi contoh utama"
npm run test:examples
```
