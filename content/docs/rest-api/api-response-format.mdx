## Overview

Envelope membantu client membedakan data dan error. Bentuk response harus konsisten, tetapi jangan memaksakan body pada response 204.

## Concept

Fokus penerapan **API Response Format** adalah gunakan data untuk payload. Tambahkan meta untuk pagination. Simpan error.code yang stabil. Contoh berikut memperlihatkan konteks kategori REST API; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Implementation

1. Gunakan data untuk payload.
2. Tambahkan meta untuk pagination.
3. Simpan error.code yang stabil.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```json title="api-response-format.json"
{"data":[{"id":"n1","title":"Backend"}],"meta":{"page":1,"limit":20}}
```

### Konteks kategori

```bash title="terminal"
curl -i http://localhost:4000/health
# HTTP 200
# {"data":{"status":"ok"}}
```

## Code Explanation

Envelope membantu client membedakan data dan error. Bentuk response harus konsisten, tetapi jangan memaksakan body pada response 204. Dalam implementasi nyata, tambahkan meta untuk pagination dan simpan error.code yang stabil sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk API Response Format, verifikasi langkah “Gunakan data untuk payload” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>

- Tambahkan meta untuk pagination.
- Batasi hak akses dan data yang dikirim ke client.
- Simpan error.code yang stabil.

## Testing

Uji API Response Format dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “gunakan data untuk payload” sesuai kontrak. Tambahkan test tanpa token dan test akses lintas user.

```bash title="verifikasi contoh utama"
npm run test:examples
```
