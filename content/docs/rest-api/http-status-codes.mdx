## Overview

Status code mengomunikasikan hasil tanpa harus membaca pesan. Bedakan 401 untuk identitas tidak valid dan 403 untuk identitas yang tidak memiliki izin.

## Concept

Fokus penerapan **HTTP Status Codes** adalah gunakan 201 saat resource dibuat. Gunakan 204 tanpa body. Gunakan 409 untuk konflik unik. Contoh berikut memperlihatkan konteks kategori REST API; sesuaikan dengan kontrak dan batas resource aplikasi.

## Code Explanation

Status code mengomunikasikan hasil tanpa harus membaca pesan. Bedakan 401 untuk identitas tidak valid dan 403 untuk identitas yang tidak memiliki izin. Dalam implementasi nyata, gunakan 204 tanpa body dan gunakan 409 untuk konflik unik sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk HTTP Status Codes, verifikasi langkah “Gunakan 201 saat resource dibuat” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>

- Gunakan 204 tanpa body.
- Batasi hak akses dan data yang dikirim ke client.
- Gunakan 409 untuk konflik unik.

## Testing

Uji HTTP Status Codes dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “gunakan 201 saat resource dibuat” sesuai kontrak. Tambahkan test tanpa token dan test akses lintas user.

```bash title="verifikasi contoh utama"
npm run test:examples
```
