## Overview

Pencarian substring cukup untuk data kecil; full-text index lebih cocok untuk skala besar. Batasi panjang query dan jangan membuat regex tak terbatas dari input user.

## Concept

Fokus penerapan **Searching** adalah normalisasi query. Gunakan parameterized query. Pertimbangkan full-text index PostgreSQL. Contoh berikut memperlihatkan konteks kategori REST API; sesuaikan dengan kontrak dan batas resource aplikasi.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="searching.mjs"
export function searchTitles(notes, query) {
  const q = query.trim().toLocaleLowerCase("id-ID");
  if (!q || q.length > 100) return [];
  return notes.filter(n => n.title.toLocaleLowerCase("id-ID").includes(q));
}
// Scope notes ke actor sebelum memanggil fungsi ini.
```

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Searching, verifikasi langkah “Normalisasi query” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
