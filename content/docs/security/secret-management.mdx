## Overview

Secret harus disediakan saat runtime oleh secret manager atau environment platform. Rotasi membutuhkan masa transisi agar key lama dapat dihentikan tanpa memutus seluruh request.

## Concept

Fokus penerapan **Secret Management** adalah pisahkan secret tiap environment. Jangan commit .env. Audit siapa yang dapat membaca secret. Contoh berikut memperlihatkan konteks kategori Security; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

Simpan latihan Secret Management pada module fitur terkait. Pisahkan transport HTTP, aturan bisnis, dan akses data agar dapat diuji secara mandiri.

## Implementation

1. Pisahkan secret tiap environment.
2. Jangan commit .env.
3. Audit siapa yang dapat membaca secret.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="secret-management.mjs"
const secret = process.env.JWT_SECRET;
if (!secret || Buffer.byteLength(secret) < 32) {
  throw new Error("JWT_SECRET tidak valid");
}
// Jangan console.log(secret), memasukkannya ke response, atau commit .env.
```

### Konteks kategori

```js title="safe-compare.mjs"
import { timingSafeEqual } from "node:crypto";
export function equalDigest(a, b) {
  if (!Buffer.isBuffer(a) || !Buffer.isBuffer(b)) return false;
  return a.length === b.length && timingSafeEqual(a, b);
}
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Secret Management, verifikasi langkah “Pisahkan secret tiap environment” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="warn" title="Batas implementasi">Contoh adalah sarana belajar dan bukan audit keamanan. Untuk production, gunakan TLS, shared persistent storage, rate limit terdistribusi, serta pengelolaan secret yang sesuai infrastruktur.</Callout>

- Jangan commit .env.
- Batasi hak akses dan data yang dikirim ke client.
- Audit siapa yang dapat membaca secret.
