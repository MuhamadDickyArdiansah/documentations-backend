## Overview

Limiter perlu menentukan key, window, dan batas berdasarkan risiko endpoint. IP di balik proxy harus diambil sesuai konfigurasi proxy yang dipercaya, bukan header mentah.

## Concept

Fokus penerapan **Rate Limiting** adalah pisahkan limiter login. Gunakan shared store. Monitor false positive dan bypass. Contoh berikut memperlihatkan konteks kategori Security; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Implementation

1. Pisahkan limiter login.
2. Gunakan shared store.
3. Monitor false positive dan bypass.

### Contoh terfokus

Periksa dependensi dan konteks pada komentar kode. Adapter seperti repository, provider, atau prisma diberikan oleh composition root; fragmen bukan server terpisah. Untuk contoh utuh, lihat [Complete Backend Starter](/docs/projects/complete-backend-starter).

```js title="rate-limiting.mjs"
import { rateLimit } from "express-rate-limit";
export const limiter = rateLimit({ windowMs: 900_000, limit: 30, standardHeaders: "draft-8", legacyHeaders: false });
// Mount pada endpoint credential; gunakan shared store untuk multi-instance.
```

## API Examples

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Rate Limiting, verifikasi langkah “Pisahkan limiter login” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="warn" title="Batas implementasi">Contoh adalah sarana belajar dan bukan audit keamanan. Untuk production, gunakan TLS, shared persistent storage, rate limit terdistribusi, serta pengelolaan secret yang sesuai infrastruktur.</Callout>

- Gunakan shared store.
- Batasi hak akses dan data yang dikirim ke client.
- Monitor false positive dan bypass.
