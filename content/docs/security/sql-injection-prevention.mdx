## Overview

Parameterized query memisahkan query dan data. Identifier seperti nama kolom sering tidak dapat diparameterisasi, sehingga harus dipilih dari allowlist.

## Concept

Fokus penerapan **SQL Injection Prevention** adalah gunakan query parameter. Hindari string concatenation. Jangan gunakan unsafe raw query untuk input user. Contoh berikut memperlihatkan konteks kategori Security; sesuaikan dengan kontrak dan batas resource aplikasi.

2. Hindari string concatenation.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```sql title="sql-injection-prevention.sql"
-- Prepared statement PostgreSQL, bukan interpolasi string dari client.
PREPARE note_for_owner(uuid, uuid) AS
SELECT id, title FROM user_notes WHERE id = $1 AND owner_id = $2;
-- Panggil menggunakan driver dengan parameter terpisah.
```

### Konteks kategori

import { timingSafeEqual } from "node:crypto";
export function equalDigest(a, b) {
  if (!Buffer.isBuffer(a) || !Buffer.isBuffer(b)) return false;
  return a.length === b.length && timingSafeEqual(a, b);
}

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk SQL Injection Prevention, verifikasi langkah “Gunakan query parameter” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
