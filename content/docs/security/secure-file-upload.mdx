## Overview

Ekstensi dan Content-Type dari client tidak dapat dipercaya. Batasi ukuran, periksa magic bytes, buat nama file acak, dan simpan di lokasi yang tidak mengeksekusi file.

## Concept

Fokus penerapan **Secure File Upload** adalah allowlist tipe file. Scan file berisiko. Gunakan private object storage dan signed URL. Contoh berikut memperlihatkan konteks kategori Security; sesuaikan dengan kontrak dan batas resource aplikasi.

### Konteks kategori

```js title="safe-compare.mjs"
import { timingSafeEqual } from "node:crypto";
export function equalDigest(a, b) {
  if (!Buffer.isBuffer(a) || !Buffer.isBuffer(b)) return false;
  return a.length === b.length && timingSafeEqual(a, b);
}
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Secure File Upload, verifikasi langkah “Allowlist tipe file” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="warn" title="Batas implementasi">Contoh adalah sarana belajar dan bukan audit keamanan. Untuk production, gunakan TLS, shared persistent storage, rate limit terdistribusi, serta pengelolaan secret yang sesuai infrastruktur.</Callout>

- Scan file berisiko.
- Batasi hak akses dan data yang dikirim ke client.
- Gunakan private object storage dan signed URL.
