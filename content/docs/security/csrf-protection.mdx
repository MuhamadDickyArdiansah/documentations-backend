## Overview

CSRF memanfaatkan credential yang dikirim browser secara otomatis. Gunakan SameSite, pemeriksaan Origin, dan token CSRF sesuai jenis request serta model lintas origin.

## Concept

Fokus penerapan **CSRF Protection** adalah lindungi endpoint mutasi. Jangan mutasi lewat GET. Uji request lintas origin. Contoh berikut memperlihatkan konteks kategori Security; sesuaikan dengan kontrak dan batas resource aplikasi.

## Implementation

1. Lindungi endpoint mutasi.
2. Jangan mutasi lewat GET.
3. Uji request lintas origin.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="csrf-protection.mjs"
const allowed = new Set(["https://app.example.com"]);
export function checkOrigin(req, res, next) {
  if (["GET", "HEAD", "OPTIONS"].includes(req.method)) return next();
  if (!allowed.has(req.headers.origin)) return res.status(403).end();
  next();
}
// Terapkan bersama SameSite dan strategi CSRF token sesuai konteks.
```

### Konteks kategori

import { timingSafeEqual } from "node:crypto";
export function equalDigest(a, b) {
  if (!Buffer.isBuffer(a) || !Buffer.isBuffer(b)) return false;
  return a.length === b.length && timingSafeEqual(a, b);
}

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk CSRF Protection, verifikasi langkah “Lindungi endpoint mutasi” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
