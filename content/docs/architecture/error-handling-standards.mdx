## Overview

Standar error menghubungkan error domain ke status HTTP secara konsisten. Kode error stabil membantu client mengambil keputusan tanpa mem-parsing pesan manusia.

## Concept

Fokus penerapan **Error Handling Standards** adalah definisikan error code. Sertakan request ID. Sembunyikan stack trace dari client. Contoh berikut memperlihatkan konteks kategori Architecture & Best Practices; sesuaikan dengan kontrak dan batas resource aplikasi.

## Implementation

1. Definisikan error code.
2. Sertakan request ID.
3. Sembunyikan stack trace dari client.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="error-handling-standards.mjs"
export class DomainError extends Error {
  constructor(code, message, options) { super(message, options); this.code = code; }
}
// Adapter HTTP memetakan code ke status. Domain tidak mengimpor Express.
```

### Konteks kategori

```js title="notes.service.mjs"
export function createNoteService(repository) {
  return {
    async findForUser(id, actor) {
      const note = await repository.findById(id);
      return note?.ownerId === actor.id ? note : null;
    },
  };
}
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Error Handling Standards, verifikasi langkah “Definisikan error code” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
