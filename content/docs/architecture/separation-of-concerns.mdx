## Overview

Setiap bagian kode perlu memiliki tanggung jawab yang jelas. Parsing HTTP, aturan bisnis, query, dan logging memiliki alasan perubahan yang berbeda.

## Concept

Fokus penerapan **Separation of Concerns** adalah pisahkan validation dan bisnis. Tempatkan logging di boundary. Hindari module utilitas serba guna. Contoh berikut memperlihatkan konteks kategori Architecture & Best Practices; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Project Structure

Simpan latihan Separation of Concerns pada module fitur terkait. Pisahkan transport HTTP, aturan bisnis, dan akses data agar dapat diuji secara mandiri.

```text title="struktur referensi"
  features/
    notes/

  server.mjs
```

## Implementation

1. Pisahkan validation dan bisnis.
2. Tempatkan logging di boundary.
3. Hindari module utilitas serba guna.

### Contoh terfokus

Periksa dependensi dan konteks pada komentar kode. Adapter seperti repository, provider, atau prisma diberikan oleh composition root; fragmen bukan server terpisah. Untuk contoh utuh, lihat [Complete Backend Starter](/docs/projects/complete-backend-starter).

```js title="separation-of-concerns.mjs"
export const normalizeTitle = value => value.trim();
export const validateTitle = value => value.length > 0 && value.length <= 200;
export async function saveTitle(repository, actor, input) {
  const title = normalizeTitle(input);
  if (!validateTitle(title)) throw new Error("Title tidak valid");
  return repository.create(actor.id, title);
}
```

### Konteks kategori

```js title="notes.service.mjs"
export function createNoteService(repository) {
  return {
    async findForUser(id, actor) {
      const note = await repository.findById(id);
      return note?.ownerId === actor.id ? note : null;
    },
  };
}
```

## Code Explanation

Setiap bagian kode perlu memiliki tanggung jawab yang jelas. Parsing HTTP, aturan bisnis, query, dan logging memiliki alasan perubahan yang berbeda. Dalam implementasi nyata, tempatkan logging di boundary dan hindari module utilitas serba guna sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Separation of Concerns, verifikasi langkah “Pisahkan validation dan bisnis” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>

- Tempatkan logging di boundary.
- Batasi hak akses dan data yang dikirim ke client.
- Hindari module utilitas serba guna.
