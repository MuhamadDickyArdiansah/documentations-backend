## Overview

Layer bergantung ke abstraksi yang lebih stabil. HTTP memanggil service, service memakai repository, dan detail database tidak bocor ke kontrak HTTP.

## Concept

Fokus penerapan **Layered Architecture** adalah definisikan boundary. Terapkan dependency direction. Uji domain tanpa server. Contoh berikut memperlihatkan konteks kategori Architecture & Best Practices; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Project Structure

Simpan latihan Layered Architecture pada module fitur terkait. Pisahkan transport HTTP, aturan bisnis, dan akses data agar dapat diuji secara mandiri.

```text title="struktur referensi"
src/
  features/
    notes/
      notes.routes.mjs
      notes.service.mjs
      notes.repository.mjs
  app.mjs
  server.mjs
```

## Implementation

1. Definisikan boundary.
2. Terapkan dependency direction.
3. Uji domain tanpa server.

### Contoh terfokus

Periksa dependensi dan konteks pada komentar kode. Adapter seperti repository, provider, atau prisma diberikan oleh composition root; fragmen bukan server terpisah. Untuk contoh utuh, lihat [Complete Backend Starter](/docs/projects/complete-backend-starter).

```js title="layered-architecture.mjs"
export function service(repository) {
  return { list: actor => repository.list(actor.id) };
}
export function controller(notesService) {
  return async (req, res) => res.json({ data: await notesService.list(req.actor) });
}
// Composition: app.get("/notes", authenticate, controller(service(repository))).
```

### Konteks kategori

```js title="notes.service.mjs"
export function createNoteService(repository) {
  return {
    async findForUser(id, actor) {
      const note = await repository.findById(id);
      return note?.ownerId === actor.id ? note : null;
    },
  };
}
```

## Code Explanation

Layer bergantung ke abstraksi yang lebih stabil. HTTP memanggil service, service memakai repository, dan detail database tidak bocor ke kontrak HTTP. Dalam implementasi nyata, terapkan dependency direction dan uji domain tanpa server sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Topik ini merupakan konsep internal, sehingga tidak mendefinisikan endpoint tersendiri. Gunakan [Basic Express API](/docs/projects/basic-express-api) untuk mempelajari cara menerapkannya pada request HTTP.

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Layered Architecture, verifikasi langkah “Definisikan boundary” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>

- Terapkan dependency direction.
- Batasi hak akses dan data yang dikirim ke client.
- Uji domain tanpa server.

## Testing

Uji Layered Architecture dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “definisikan boundary” sesuai kontrak. 

```bash title="verifikasi contoh utama"
npm run test:examples
```
