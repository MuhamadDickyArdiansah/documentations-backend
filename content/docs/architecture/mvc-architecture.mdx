## Overview

MVC memisahkan model, representasi, dan controller. Dalam JSON API, representasi biasanya DTO, sedangkan aturan bisnis sebaiknya tetap berada di service atau domain.

## Concept

Fokus penerapan **MVC Architecture** adalah jaga controller kecil. Pisahkan serializer. Jangan menyamakan model database dengan response. Contoh berikut memperlihatkan konteks kategori Architecture & Best Practices; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Project Structure

Simpan latihan MVC Architecture pada module fitur terkait. Pisahkan transport HTTP, aturan bisnis, dan akses data agar dapat diuji secara mandiri.

```text title="struktur referensi"
src/
  features/
    notes/
      notes.routes.mjs
      notes.service.mjs
      notes.repository.mjs
  app.mjs
  server.mjs
```

## Implementation

1. Jaga controller kecil.
2. Pisahkan serializer.
3. Jangan menyamakan model database dengan response.

### Contoh terfokus

Periksa dependensi dan konteks pada komentar kode. Adapter seperti repository, provider, atau prisma diberikan oleh composition root; fragmen bukan server terpisah. Untuk contoh utuh, lihat [Complete Backend Starter](/docs/projects/complete-backend-starter).

```text title="mvc-architecture.text"
POST /notes
  -> Controller: parse DTO dan actor
  -> Service: jalankan aturan bisnis
  -> Model/Repository: simpan data
  -> Serializer: pilih field response publik
```

### Konteks kategori

```js title="notes.service.mjs"
export function createNoteService(repository) {
  return {
    async findForUser(id, actor) {
      const note = await repository.findById(id);
      return note?.ownerId === actor.id ? note : null;
    },
  };
}
```

## Code Explanation

Dalam implementasi nyata, pisahkan serializer dan jangan menyamakan model database dengan response sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk MVC Architecture, verifikasi langkah “Jaga controller kecil” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>

- Pisahkan serializer.
- Batasi hak akses dan data yang dikirim ke client.
- Jangan menyamakan model database dengan response.
