## Overview

Log operasional harus menjawab apa yang gagal dan di request mana. Standardisasi field dan redaction mengurangi biaya investigasi dan risiko kebocoran.

## Concept

Fokus penerapan **Logging Standards** adalah gunakan JSON. Sertakan service dan requestId. Jangan log body mentah secara default. Contoh berikut memperlihatkan konteks kategori Architecture & Best Practices; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Implementation

1. Gunakan JSON.
2. Sertakan service dan requestId.
3. Jangan log body mentah secara default.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="logging-standards.mjs"
export function logEvent(level, event, context = {}) {
  const { requestId, resourceId } = context;
  console.log(JSON.stringify({ level, event, requestId, resourceId, at: new Date().toISOString() }));
}
// Allowlist field; jangan menerima arbitrary request body.
```

### Konteks kategori

```js title="notes.service.mjs"
export function createNoteService(repository) {
  return {
    async findForUser(id, actor) {
      const note = await repository.findById(id);
      return note?.ownerId === actor.id ? note : null;
    },
  };
}
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Logging Standards, verifikasi langkah “Gunakan JSON” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices
