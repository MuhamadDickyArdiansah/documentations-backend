## Overview

Liveness menunjukkan proses masih hidup; readiness menunjukkan proses siap melayani request. Jangan membuat liveness gagal hanya karena dependensi sementara lambat.

## Concept

Fokus penerapan **Health Checks** adalah pisahkan /health dan /ready. Gunakan timeout. Jangan bocorkan konfigurasi internal. Contoh berikut memperlihatkan konteks kategori Deployment; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Implementation

1. Pisahkan /health dan /ready.
2. Gunakan timeout.
3. Jangan bocorkan konfigurasi internal.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="health-checks.mjs"
export function registerHealth(app) {
  app.get("/health", (_req, res) => res.json({ data: { status: "ok" } }));
}
// Readiness database memerlukan handler terpisah dengan timeout.
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Health Checks, verifikasi langkah “Pisahkan /health dan /ready” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
