## Overview

Monitoring menghubungkan metrik, log, dan trace dengan dampak pengguna. Mulai dari traffic, error rate, latency, dan saturation sebelum menambah banyak dashboard.

## Concept

Fokus penerapan **Monitoring** adalah tentukan SLO. Pantau p95 latency. Gunakan alert yang dapat ditindaklanjuti. Contoh berikut memperlihatkan konteks kategori Deployment; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Project Structure

Simpan latihan Monitoring pada module fitur terkait. Pisahkan transport HTTP, aturan bisnis, dan akses data agar dapat diuji secara mandiri.


## Implementation

1. Tentukan SLO.
2. Pantau p95 latency.
3. Gunakan alert yang dapat ditindaklanjuti.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="monitoring.mjs"
export function durationMetric(start, status) {
  return { durationMs: performance.now() - start, status };
}
// Kirim metric ke backend observability; hindari label ber-cardinality tinggi.
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Monitoring, verifikasi langkah “Tentukan SLO” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
