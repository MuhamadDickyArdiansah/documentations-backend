## Overview

Pipeline memverifikasi perubahan sebelum rilis dan mengotomatisasi deployment yang dapat dilacak. Secret deployment harus dibatasi ke environment serta branch yang dipercaya.

## Concept

Fokus penerapan **CI/CD** adalah jalankan install deterministik. Jalankan test dan build. Sediakan rollback ke versi sebelumnya. Contoh berikut memperlihatkan konteks kategori Deployment; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Project Structure

Simpan latihan CI/CD pada module fitur terkait. Pisahkan transport HTTP, aturan bisnis, dan akses data agar dapat diuji secara mandiri.

```text title="struktur referensi"
src/
  features/
    notes/
      notes.routes.mjs
      notes.service.mjs
      notes.repository.mjs
  app.mjs
  server.mjs
```

## Implementation

1. Jalankan install deterministik.
2. Jalankan test dan build.
3. Sediakan rollback ke versi sebelumnya.

### Contoh terfokus

Periksa dependensi dan konteks pada komentar kode. Adapter seperti repository, provider, atau prisma diberikan oleh composition root; fragmen bukan server terpisah. Untuk contoh utuh, lihat [Complete Backend Starter](/docs/projects/complete-backend-starter).

```yaml title="ci-cd.yaml"
name: Backend checks
on: [push, pull_request]
permissions:
  contents: read
jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm
      - run: npm ci
      - run: npm run test:examples
      - run: npm run build
```

### Konteks kategori

```bash title="terminal"
npm ci
npm run test:examples
npm run build
# Atur environment platform, lalu jalankan smoke test setelah deploy.
```

## Code Explanation

Pipeline memverifikasi perubahan sebelum rilis dan mengotomatisasi deployment yang dapat dilacak. Secret deployment harus dibatasi ke environment serta branch yang dipercaya. Dalam implementasi nyata, jalankan test dan build dan sediakan rollback ke versi sebelumnya sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Topik ini merupakan konsep internal, sehingga tidak mendefinisikan endpoint tersendiri. Gunakan [Basic Express API](/docs/projects/basic-express-api) untuk mempelajari cara menerapkannya pada request HTTP.

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk CI/CD, verifikasi langkah “Jalankan install deterministik” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>

- Jalankan test dan build.
- Batasi hak akses dan data yang dikirim ke client.
- Sediakan rollback ke versi sebelumnya.

## Testing

Uji CI/CD dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “jalankan install deterministik” sesuai kontrak. 

```bash title="verifikasi contoh utama"
npm run test:examples
```
