## Overview

Environment production harus divalidasi sebelum menerima traffic. Pisahkan build-time public configuration dari runtime secret dan hindari fallback credential pada production.

## Concept

Fokus penerapan **Environment Configuration** adalah validasi konfigurasi startup. Pisahkan staging dan production. Jangan mencetak secret saat error. Contoh berikut memperlihatkan konteks kategori Deployment; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Implementation

1. Validasi konfigurasi startup.
2. Pisahkan staging dan production.
3. Jangan mencetak secret saat error.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="environment-configuration.mjs"
const origin = new URL(process.env.NEXT_PUBLIC_SITE_URL || "http://localhost:3000");
if (process.env.NODE_ENV === "production" && origin.protocol !== "https:") {
  throw new Error("Production origin harus HTTPS");
}
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Environment Configuration, verifikasi langkah “Validasi konfigurasi startup” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
