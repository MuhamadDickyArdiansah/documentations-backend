## Overview

MFA menambah faktor independen selain password. TOTP memerlukan secret terenkripsi, perlindungan replay per time-step, rate limit, dan recovery code sekali pakai.

## Concept

Fokus penerapan **Multi-Factor Authentication** adalah verifikasi faktor saat enrollment. Simpan recovery code sebagai hash. Minta reauthentication untuk menonaktifkan MFA. Contoh berikut memperlihatkan konteks kategori Authentication; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

## Installation

Dari root repository, jalankan perintah berikut. Dependensi contoh dikelola bersama lockfile project.

```bash title="terminal"
npm ci
npm run examples
```

## Project Structure

Simpan latihan Multi-Factor Authentication pada module fitur terkait. Pisahkan transport HTTP, aturan bisnis, dan akses data agar dapat diuji secara mandiri.

## Implementation

1. Verifikasi faktor saat enrollment.
2. Simpan recovery code sebagai hash.
3. Minta reauthentication untuk menonaktifkan MFA.

### Contoh terfokus

Cuplikan route memakai helper dan state dari examples/complete-backend/app.mjs. Implementasi lengkap yang dapat dijalankan ada pada [JWT Authentication](/docs/authentication/jwt-authentication). Cuplikan modul mandiri dapat disimpan sebagai .mjs; import examples menggunakan path relatif dari root repository.

```js title="multi-factor-authentication.mjs"
import { randomBytes, createHash } from "node:crypto";
const recoveryCodes = Array.from({ length: 8 }, () => randomBytes(12).toString("base64url"));
const hashes = recoveryCodes.map(code => createHash("sha256").update(code).digest("hex"));
// Tampilkan recoveryCodes hanya sekali; simpan hashes dan status consumed.
// Consume satu code secara atomik. Ini pelengkap MFA, bukan implementasi TOTP.
```

### Konteks kategori

```bash title="terminal"
curl -i -X POST http://localhost:4000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"reader@example.com","password":"a-long-example-password"}'
```

## Code Explanation

MFA menambah faktor independen selain password. TOTP memerlukan secret terenkripsi, perlindungan replay per time-step, rate limit, dan recovery code sekali pakai. Dalam implementasi nyata, simpan recovery code sebagai hash dan minta reauthentication untuk menonaktifkan mfa sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Multi-Factor Authentication, verifikasi langkah “Verifikasi faktor saat enrollment” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="warn" title="Batas implementasi">Contoh adalah sarana belajar dan bukan audit keamanan. Untuk production, gunakan TLS, shared persistent storage, rate limit terdistribusi, serta pengelolaan secret yang sesuai infrastruktur.</Callout>

- Simpan recovery code sebagai hash.
- Batasi hak akses dan data yang dikirim ke client.
- Minta reauthentication untuk menonaktifkan MFA.

## Testing

Uji Multi-Factor Authentication dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “verifikasi faktor saat enrollment” sesuai kontrak. Tambahkan test tanpa token dan test akses lintas user.

```bash title="verifikasi contoh utama"
npm run test:examples
```
