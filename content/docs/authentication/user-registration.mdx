## Overview

Registrasi memvalidasi email dan password lalu membuat identitas unik. Constraint unik pada database diperlukan untuk menangani request bersamaan.

## Concept

Fokus penerapan **User Registration** adalah normalisasi email. Hash sebelum menyimpan. Tangani duplicate email sebagai 409. Contoh berikut memperlihatkan konteks kategori Authentication; sesuaikan dengan kontrak dan batas resource aplikasi.

## Implementation

1. Normalisasi email.
2. Hash sebelum menyimpan.
3. Tangani duplicate email sebagai 409.

### Contoh terfokus

Cuplikan route memakai helper dan state dari examples/complete-backend/app.mjs. Implementasi lengkap yang dapat dijalankan ada pada [JWT Authentication](/docs/authentication/jwt-authentication). Cuplikan modul mandiri dapat disimpan sebagai .mjs; import examples menggunakan path relatif dari root repository.

```js title="user-registration.mjs"
app.post('/api/auth/register', async (req, res) => {
    const data = parse(credentials, req.body, res); if (!data) return;
    const passwordHash = await hashPassword(data.password);
    // This synchronous check+insert is atomic only within this single-process demo.
    if ([...users.values()].some(u => u.email === data.email)) return error(res, 409, 'EMAIL_EXISTS', 'Email sudah digunakan.');
    const user = { id: randomUUID(), email: data.email, passwordHash, role: 'user' };
    users.set(user.id, user);
    return res.status(201).json({ data: { id: user.id, email: user.email, role: user.role } });
  });
```

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk User Registration, verifikasi langkah “Normalisasi email” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
