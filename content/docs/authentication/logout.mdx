## Overview

Logout mencabut sesi server dan menghapus credential client. Menghapus token dari UI saja tidak menonaktifkan token yang sudah dicuri.

## Concept

Fokus penerapan **Logout** adalah cabut refresh session. Kosongkan cookie dengan atribut yang sama. Dokumentasikan sisa umur access token. Contoh berikut memperlihatkan konteks kategori Authentication; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

## Installation

Dari root repository, jalankan perintah berikut. Dependensi contoh dikelola bersama lockfile project.

```bash title="terminal"
npm ci
npm run examples
```

Simpan latihan Logout pada module fitur terkait. Pisahkan transport HTTP, aturan bisnis, dan akses data agar dapat diuji secara mandiri.

## Implementation

1. Cabut refresh session.
2. Kosongkan cookie dengan atribut yang sama.
3. Dokumentasikan sisa umur access token.

### Contoh terfokus

Cuplikan route memakai helper dan state dari examples/complete-backend/app.mjs. Implementasi lengkap yang dapat dijalankan ada pada [JWT Authentication](/docs/authentication/jwt-authentication). Cuplikan modul mandiri dapat disimpan sebagai .mjs; import examples menggunakan path relatif dari root repository.

```js title="logout.mjs"
// Dipasang setelah fungsi authenticate pada complete-backend/app.mjs.
app.post('/api/auth/logout', authenticate, (req, res) => {
  sessions.get(req.sessionId).revoked = true;
  res.status(204).end();
});
```

### Konteks kategori

## Code Explanation

Logout mencabut sesi server dan menghapus credential client. Menghapus token dari UI saja tidak menonaktifkan token yang sudah dicuri. Dalam implementasi nyata, kosongkan cookie dengan atribut yang sama dan dokumentasikan sisa umur access token sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Logout, verifikasi langkah “Cabut refresh session” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="warn" title="Batas implementasi">Contoh adalah sarana belajar dan bukan audit keamanan. Untuk production, gunakan TLS, shared persistent storage, rate limit terdistribusi, serta pengelolaan secret yang sesuai infrastruktur.</Callout>

- Kosongkan cookie dengan atribut yang sama.
- Batasi hak akses dan data yang dikirim ke client.
- Dokumentasikan sisa umur access token.

## Testing

Uji Logout dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “cabut refresh session” sesuai kontrak. Tambahkan test tanpa token dan test akses lintas user.

```bash title="verifikasi contoh utama"
npm run test:examples
```
