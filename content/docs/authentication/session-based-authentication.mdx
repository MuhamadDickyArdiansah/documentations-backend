## Overview

Session menyimpan state identitas pada server dan ID acak pada cookie. Regenerasi session ID setelah login mencegah session fixation.

## Concept

Fokus penerapan **Session-Based Authentication** adalah pilih shared session store. Regenerasi setelah login. Tetapkan idle dan absolute timeout. Contoh berikut memperlihatkan konteks kategori Authentication; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

## Installation

Dari root repository, jalankan perintah berikut. Dependensi contoh dikelola bersama lockfile project.

```bash title="terminal"
npm ci
npm run examples
```

## Project Structure

Simpan latihan Session-Based Authentication pada module fitur terkait. Pisahkan transport HTTP, aturan bisnis, dan akses data agar dapat diuji secara mandiri.

```text title="struktur referensi"
src/
  features/
    notes/
      notes.routes.mjs
      notes.service.mjs

  app.mjs
  server.mjs
```

## Implementation

1. Pilih shared session store.
2. Regenerasi setelah login.
3. Tetapkan idle dan absolute timeout.

### Contoh terfokus

Cuplikan route memakai helper dan state dari examples/complete-backend/app.mjs. Implementasi lengkap yang dapat dijalankan ada pada [JWT Authentication](/docs/authentication/jwt-authentication). Cuplikan modul mandiri dapat disimpan sebagai .mjs; import examples menggunakan path relatif dari root repository.

```js title="session-based-authentication.mjs"
import { randomBytes, createHash } from "node:crypto";
const sessionId = randomBytes(32).toString("base64url");
const key = createHash("sha256").update(sessionId).digest("hex");
// Simpan key, userId, createdAt, expiresAt pada shared store.
// Kirim sessionId dalam cookie HttpOnly, Secure, SameSite.
// Regenerasi ID setelah login dan perubahan tingkat privilege.
```

### Konteks kategori

```bash title="terminal"
curl -i -X POST http://localhost:4000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"reader@example.com","password":"a-long-example-password"}'
```

## Code Explanation

Session menyimpan state identitas pada server dan ID acak pada cookie. Regenerasi session ID setelah login mencegah session fixation. Dalam implementasi nyata, regenerasi setelah login dan tetapkan idle dan absolute timeout sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Session-Based Authentication, verifikasi langkah “Pilih shared session store” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="warn" title="Batas implementasi">Contoh adalah sarana belajar dan bukan audit keamanan. Untuk production, gunakan TLS, shared persistent storage, rate limit terdistribusi, serta pengelolaan secret yang sesuai infrastruktur.</Callout>

- Regenerasi setelah login.
- Batasi hak akses dan data yang dikirim ke client.
- Tetapkan idle dan absolute timeout.

## Testing

Uji Session-Based Authentication dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “pilih shared session store” sesuai kontrak. Tambahkan test tanpa token dan test akses lintas user.

```bash title="verifikasi contoh utama"
npm run test:examples
```
