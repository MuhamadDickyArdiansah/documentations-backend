## Overview

Reset memvalidasi token sekali pakai secara atomik, memperbarui hash password, dan mencabut sesi lama. Jangan otomatis login setelah reset tanpa keputusan keamanan yang jelas.

## Concept

Fokus penerapan **Reset Password** adalah validasi token dan expiry. Tandai token terpakai. Cabut sesi dan kirim notifikasi. Contoh berikut memperlihatkan konteks kategori Authentication; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

## Implementation

1. Validasi token dan expiry.
2. Tandai token terpakai.
3. Cabut sesi dan kirim notifikasi.

### Contoh terfokus

Cuplikan route memakai helper dan state dari examples/complete-backend/app.mjs. Implementasi lengkap yang dapat dijalankan ada pada [JWT Authentication](/docs/authentication/jwt-authentication). Cuplikan modul mandiri dapat disimpan sebagai .mjs; import examples menggunakan path relatif dari root repository.

```sql title="reset-password.sql"
-- Setelah membuat tabel password_reset_tokens dengan kolom berikut:
-- id uuid, token_hash text UNIQUE, expires_at timestamptz, used_at timestamptz.
-- Jalankan dalam transaksi bersama update password dan revocation sesi.
UPDATE password_reset_tokens SET used_at = now()
WHERE token_hash = $1 AND used_at IS NULL AND expires_at > now()
RETURNING id;
-- $1 adalah parameter driver, bukan interpolasi string.
-- Jika tidak ada row, tolak reset tanpa mengungkap penyebab rinci.
```

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Reset Password, verifikasi langkah “Validasi token dan expiry” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices
