## Overview

Verifikasi email membuktikan akses pada inbox, bukan identitas legal pemiliknya. Token verifikasi harus terikat ke user dan email yang sedang diverifikasi.

## Concept

Fokus penerapan **Email Verification** adalah kirim token sekali pakai. Batasi kirim ulang. Periksa verifiedAt sebelum fitur sensitif. Contoh berikut memperlihatkan konteks kategori Authentication; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

Dari root repository, jalankan perintah berikut. Dependensi contoh dikelola bersama lockfile project.

## Implementation

1. Kirim token sekali pakai.
2. Batasi kirim ulang.
3. Periksa verifiedAt sebelum fitur sensitif.

### Contoh terfokus

Cuplikan route memakai helper dan state dari examples/complete-backend/app.mjs. Implementasi lengkap yang dapat dijalankan ada pada [JWT Authentication](/docs/authentication/jwt-authentication). Cuplikan modul mandiri dapat disimpan sebagai .mjs; import examples menggunakan path relatif dari root repository.

```sql title="email-verification.sql"
-- Kontrak tabel: email_verifications(user_id, email, token_hash, expires_at, used_at).
-- Consume token sekali pakai dalam transaksi bersama update user.
UPDATE email_verifications SET used_at = now()
WHERE token_hash = $1 AND used_at IS NULL AND expires_at > now()
RETURNING user_id, email;
-- Hanya tandai email yang sama dengan record hasil RETURNING.
```

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Email Verification, verifikasi langkah “Kirim token sekali pakai” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="warn" title="Batas implementasi">Contoh adalah sarana belajar dan bukan audit keamanan. Untuk production, gunakan TLS, shared persistent storage, rate limit terdistribusi, serta pengelolaan secret yang sesuai infrastruktur.</Callout>

- Batasi kirim ulang.
- Batasi hak akses dan data yang dikirim ke client.
- Periksa verifiedAt sebelum fitur sensitif.

## Testing

Uji Email Verification dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “kirim token sekali pakai” sesuai kontrak. Tambahkan test tanpa token dan test akses lintas user.

```bash title="verifikasi contoh utama"
npm run test:examples
```
