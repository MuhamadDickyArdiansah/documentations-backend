## Overview

Transaksi memastikan sejumlah write berhasil atau gagal bersama. Tingkat isolasi dan conflict handling menentukan perilaku pada akses bersamaan.

## Concept

Fokus penerapan **Transactions** adalah jaga transaksi singkat. Hindari network call dalam transaksi. Retry konflik yang dapat dipulihkan. Contoh berikut memperlihatkan konteks kategori Database; sesuaikan dengan kontrak dan batas resource aplikasi.

## Implementation

1. Jaga transaksi singkat.
2. Hindari network call dalam transaksi.
3. Retry konflik yang dapat dipulihkan.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```sql title="transactions.sql"
BEGIN;
INSERT INTO users (id, email)
VALUES ('00000000-0000-4000-8000-000000000001', 'demo@example.com');
INSERT INTO user_notes (id, owner_id, title)
VALUES ('00000000-0000-4000-8000-000000000002',
        '00000000-0000-4000-8000-000000000001', 'First note');
COMMIT;
-- Jalankan setelah membuat tabel users dan user_notes.
```

### Konteks kategori

```sql title="schema.sql"
CREATE TABLE notes (
  id uuid PRIMARY KEY,
  owner_id uuid NOT NULL,
  title varchar(200) NOT NULL CHECK (length(title) > 0),
  created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX notes_owner_created_idx ON notes(owner_id, created_at DESC, id);
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Transactions, verifikasi langkah “Jaga transaksi singkat” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
