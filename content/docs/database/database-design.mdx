## Overview

Desain schema dimulai dari invariant domain dan relasi. Normalisasi mengurangi inkonsistensi; denormalisasi harus didorong pengukuran dan memiliki strategi sinkronisasi.

## Concept

Fokus penerapan **Database Design** adalah tentukan entitas. Pilih constraint. Definisikan lifecycle data. Contoh berikut memperlihatkan konteks kategori Database; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai PostgreSQL. Jalankan SQL pada database development melalui psql atau SQL editor.

## Implementation

1. Tentukan entitas.
2. Pilih constraint.
3. Definisikan lifecycle data.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```sql title="database-design.sql"
CREATE TABLE accounts (
  id uuid PRIMARY KEY,
  owner_id uuid NOT NULL REFERENCES users(id),
  currency char(3) NOT NULL,
  balance_minor bigint NOT NULL CHECK (balance_minor >= 0)
);
```

### Konteks kategori

```sql title="schema.sql"
CREATE TABLE notes (
  id uuid PRIMARY KEY,
  owner_id uuid NOT NULL,
  title varchar(200) NOT NULL CHECK (length(title) > 0),
  created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX notes_owner_created_idx ON notes(owner_id, created_at DESC, id);
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Database Design, verifikasi langkah “Tentukan entitas” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>
