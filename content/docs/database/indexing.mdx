## Overview

Index mempercepat pembacaan tertentu tetapi menambah biaya write dan storage. Urutan kolom composite index harus sesuai filter dan sort query yang sering dijalankan.

## Concept

Fokus penerapan **Indexing** adalah periksa EXPLAIN. Buat index untuk foreign key yang sering di-query. Hapus index redundan setelah pengukuran. Contoh berikut memperlihatkan konteks kategori Database; sesuaikan dengan kontrak dan batas resource aplikasi.

## Implementation

1. Periksa EXPLAIN.
2. Buat index untuk foreign key yang sering di-query.
3. Hapus index redundan setelah pengukuran.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```sql title="indexing.sql"
CREATE INDEX user_notes_owner_title_idx ON user_notes(owner_id, title, id);
EXPLAIN SELECT id, title FROM user_notes
WHERE owner_id = '00000000-0000-4000-8000-000000000001'
ORDER BY title, id LIMIT 20;
```

### Konteks kategori

```sql title="schema.sql"
CREATE TABLE notes (
  id uuid PRIMARY KEY,
  owner_id uuid NOT NULL,
  title varchar(200) NOT NULL CHECK (length(title) > 0),
  created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX notes_owner_created_idx ON notes(owner_id, created_at DESC, id);
```
