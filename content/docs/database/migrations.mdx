## Overview

Migration adalah riwayat perubahan struktur database. Jangan mengedit migration yang sudah diterapkan; buat perubahan baru dan jalankan migrate deploy di production.

## Concept

Fokus penerapan **Migrations** adalah review SQL hasil generate. Uji pada salinan data. Gunakan expand-contract untuk perubahan breaking. Contoh berikut memperlihatkan konteks kategori Database; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai PostgreSQL. Jalankan SQL pada database development melalui psql atau SQL editor.

## Project Structure

Simpan latihan Migrations pada module fitur terkait. Pisahkan transport HTTP, aturan bisnis, dan akses data agar dapat diuji secara mandiri.


## Implementation

1. Review SQL hasil generate.
2. Uji pada salinan data.
3. Gunakan expand-contract untuk perubahan breaking.

### Konteks kategori

```sql title="schema.sql"
CREATE TABLE notes (
  id uuid PRIMARY KEY,
  owner_id uuid NOT NULL,
  title varchar(200) NOT NULL CHECK (length(title) > 0),
  created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX notes_owner_created_idx ON notes(owner_id, created_at DESC, id);
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Migrations, verifikasi langkah “Review SQL hasil generate” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
