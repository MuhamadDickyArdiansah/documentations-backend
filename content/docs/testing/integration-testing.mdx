## Overview

Integration test memverifikasi beberapa komponen yang bekerja bersama. Database test harus terisolasi dan tidak pernah menggunakan credential production.

## Concept

Fokus penerapan **Integration Testing** adalah gunakan database test. Jalankan migration. Bersihkan fixture secara terkontrol. Contoh berikut memperlihatkan konteks kategori Testing; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Project Structure

Simpan latihan Integration Testing pada module fitur terkait. Pisahkan transport HTTP, aturan bisnis, dan akses data agar dapat diuji secara mandiri.

```text title="struktur referensi"
src/
  features/
    notes/
      notes.routes.mjs
      notes.service.mjs
      notes.repository.mjs
  app.mjs
  server.mjs
```

## Implementation

1. Gunakan database test.
2. Jalankan migration.
3. Bersihkan fixture secara terkontrol.

### Contoh terfokus

Periksa dependensi dan konteks pada komentar kode. Adapter seperti repository, provider, atau prisma diberikan oleh composition root; fragmen bukan server terpisah. Untuk contoh utuh, lihat [Complete Backend Starter](/docs/projects/complete-backend-starter).

```bash title="integration-testing.bash"
npm run test:examples
# Test memakai port 0, state aplikasi baru, HTTP nyata, dan teardown server.
```

### Konteks kategori

```js title="policy.test.mjs"
import test from "node:test";
import assert from "node:assert/strict";
const canRead = (actor, resource) => actor.id === resource.ownerId;
test("menolak akses lintas owner", () => {
  assert.equal(canRead({ id: "u2" }, { ownerId: "u1" }), false);
});
```

## Code Explanation

Integration test memverifikasi beberapa komponen yang bekerja bersama. Database test harus terisolasi dan tidak pernah menggunakan credential production. Dalam implementasi nyata, jalankan migration dan bersihkan fixture secara terkontrol sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Topik ini merupakan konsep internal, sehingga tidak mendefinisikan endpoint tersendiri. Gunakan [Basic Express API](/docs/projects/basic-express-api) untuk mempelajari cara menerapkannya pada request HTTP.

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Integration Testing, verifikasi langkah “Gunakan database test” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>

- Jalankan migration.
- Batasi hak akses dan data yang dikirim ke client.
- Bersihkan fixture secara terkontrol.

## Testing

Uji Integration Testing dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “gunakan database test” sesuai kontrak. 

```bash title="verifikasi contoh utama"
npm run test:examples
```
