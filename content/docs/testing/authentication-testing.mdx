## Overview

Test authentication harus mencakup credential salah, token kedaluwarsa, signature tidak valid, refresh replay, dan logout. Happy path saja tidak membuktikan kontrol akses.

## Concept

Fokus penerapan **Authentication Testing** adalah uji 401 tanpa token. Uji rotasi refresh. Uji token ditolak setelah logout. Contoh berikut memperlihatkan konteks kategori Testing; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Implementation

1. Uji 401 tanpa token.
2. Uji rotasi refresh.
3. Uji token ditolak setelah logout.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```bash title="authentication-testing.bash"
node --test examples/backend.test.mjs

```

### Konteks kategori

```js title="policy.test.mjs"
import test from "node:test";
import assert from "node:assert/strict";
const canRead = (actor, resource) => actor.id === resource.ownerId;
test("menolak akses lintas owner", () => {
  assert.equal(canRead({ id: "u2" }, { ownerId: "u1" }), false);
});
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Authentication Testing, verifikasi langkah “Uji 401 tanpa token” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
