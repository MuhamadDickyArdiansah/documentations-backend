## Overview

Mock mengganti dependensi yang lambat atau sulit dikontrol. Terlalu banyak mock dapat menyembunyikan kesalahan kontrak dengan library atau database sebenarnya.

## Concept

Fokus penerapan **Mocking** adalah mock provider eksternal. Gunakan fake sederhana. Tambahkan integration test untuk adapter nyata. Contoh berikut memperlihatkan konteks kategori Testing; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

Simpan latihan Mocking pada module fitur terkait. Pisahkan transport HTTP, aturan bisnis, dan akses data agar dapat diuji secara mandiri.

## Implementation

1. Mock provider eksternal.
2. Gunakan fake sederhana.
3. Tambahkan integration test untuk adapter nyata.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="mocking.mjs"
const fakeRepository = { async findById(id) { return { id, ownerId: "u1" }; } };
export function service(repository) {
  return async (id, actor) => {
    const note = await repository.findById(id);
    return note.ownerId === actor.id ? note : null;
  };
}
console.assert(await service(fakeRepository)("n1", { id: "u2" }) === null);
```

### Konteks kategori

```js title="policy.test.mjs"
import test from "node:test";
import assert from "node:assert/strict";
const canRead = (actor, resource) => actor.id === resource.ownerId;
test("menolak akses lintas owner", () => {
  assert.equal(canRead({ id: "u2" }, { ownerId: "u1" }), false);
});
```

## Code Explanation

Mock mengganti dependensi yang lambat atau sulit dikontrol. Terlalu banyak mock dapat menyembunyikan kesalahan kontrak dengan library atau database sebenarnya. Dalam implementasi nyata, gunakan fake sederhana dan tambahkan integration test untuk adapter nyata sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Mocking, verifikasi langkah “Mock provider eksternal” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>

- Gunakan fake sederhana.
- Batasi hak akses dan data yang dikirim ke client.
- Tambahkan integration test untuk adapter nyata.
