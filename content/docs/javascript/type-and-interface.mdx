## Overview

interface cocok untuk bentuk object yang dapat diperluas; type mendukung union dan komposisi tipe. Gunakan discriminated union untuk memodelkan status sukses dan gagal.

## Concept

Fokus penerapan **Type & Interface** adalah pisahkan tipe domain dan DTO. Hindari any. Gunakan readonly pada data yang tidak boleh dimutasi. Contoh berikut memperlihatkan konteks kategori JavaScript & TypeScript; sesuaikan dengan kontrak dan batas resource aplikasi.

## Implementation

1. Pisahkan tipe domain dan DTO.
2. Hindari any.
3. Gunakan readonly pada data yang tidak boleh dimutasi.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```ts title="type-and-interface.ts"
interface Note { id: string; title: string }
type Result<T> = { ok: true; data: T } | { ok: false; code: string };
function unwrap(result: Result<Note>): string {
  return result.ok ? result.data.title : result.code;
}
```

### Konteks kategori

```js title="example.mjs"
const notes = [{ id: 1, title: "Belajar backend", done: false }];
const titles = notes.filter(note => !note.done).map(note => note.title);
console.log(titles);
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Type & Interface, verifikasi langkah “Pisahkan tipe domain dan DTO” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
