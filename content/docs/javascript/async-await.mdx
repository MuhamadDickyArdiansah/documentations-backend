## Overview

async selalu mengembalikan Promise. await membuat alur asinkron lebih mudah dibaca, tetapi await berurutan dapat memperlambat operasi yang sebenarnya independen.

## Concept

Fokus penerapan **Async/Await** adalah gunakan try/catch di batas request. Paralelkan pekerjaan independen. Jangan gunakan async callback dalam forEach. Contoh berikut memperlihatkan konteks kategori JavaScript & TypeScript; sesuaikan dengan kontrak dan batas resource aplikasi.

## Implementation

1. Gunakan try/catch di batas request.
2. Paralelkan pekerjaan independen.
3. Jangan gunakan async callback dalam forEach.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="async-await.mjs"
export async function loadWithTimeout(url) {
  const response = await fetch(url, { signal: AbortSignal.timeout(3000) });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}
// URL ditentukan server dari konfigurasi yang dipercaya.
```

### Konteks kategori

```js title="example.mjs"
const notes = [{ id: 1, title: "Belajar backend", done: false }];
const titles = notes.filter(note => !note.done).map(note => note.title);
console.log(titles);
```

## Code Explanation

async selalu mengembalikan Promise. await membuat alur asinkron lebih mudah dibaca, tetapi await berurutan dapat memperlambat operasi yang sebenarnya independen. Dalam implementasi nyata, paralelkan pekerjaan independen dan jangan gunakan async callback dalam foreach sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Async/Await, verifikasi langkah “Gunakan try/catch di batas request” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices
