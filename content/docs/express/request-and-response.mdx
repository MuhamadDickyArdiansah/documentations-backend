## Overview

Body dan query adalah input tak terpercaya. Response harus menggunakan field allowlist agar hash password atau field internal tidak ikut terserialisasi.

## Concept

Fokus penerapan **Request & Response** adalah tetapkan JSON limit. Parse query secara eksplisit. Gunakan response envelope yang konsisten. Contoh berikut memperlihatkan konteks kategori Express.js; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

## Installation

Dari root repository, jalankan perintah berikut. Dependensi contoh dikelola bersama lockfile project.

```bash title="terminal"
npm ci
npm run examples
```

## Implementation

1. Tetapkan JSON limit.
2. Parse query secara eksplisit.
3. Gunakan response envelope yang konsisten.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="request-and-response.mjs"
export function publicUser(user) {
  return { id: user.id, email: user.email };
}
// Controller: res.status(201).json({ data: publicUser(created) });
```

### Konteks kategori

```js title="app.mjs"
import express from "express";
const app = express();
app.use(express.json({ limit: "16kb" }));
app.get("/health", (_req, res) => res.json({ data: { status: "ok" } }));
app.use((_req, res) => res.status(404).json({ error: { code: "NOT_FOUND" } }));
app.listen(4000, "127.0.0.1");
```

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Request & Response, verifikasi langkah “Tetapkan JSON limit” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Testing

Uji Request & Response dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “tetapkan json limit” sesuai kontrak. Tambahkan test tanpa token dan test akses lintas user.

```bash title="verifikasi contoh utama"
npm run test:examples
```
