## Overview

Express 5 meneruskan rejection dari async handler ke error middleware. Middleware error memakai empat parameter dan memeriksa headersSent sebelum menulis response.

## Concept

Fokus penerapan **Error Handling** adalah definisikan HttpError. Pasang error handler terakhir. Kirim pesan umum untuk status 500. Contoh berikut memperlihatkan konteks kategori Express.js; sesuaikan dengan kontrak dan batas resource aplikasi.

## Implementation

1. Definisikan HttpError.
2. Pasang error handler terakhir.
3. Kirim pesan umum untuk status 500.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="error-handling.mjs"
export function errorHandler(error, req, res, next) {
  if (res.headersSent) return next(error);
  if (error.type === "entity.parse.failed") {
    return res.status(400).json({ error: { code: "INVALID_JSON", message: "JSON tidak valid" } });
  }
  res.status(500).json({ error: { code: "INTERNAL_ERROR", message: "Terjadi kesalahan internal" } });
}
// app.use(errorHandler) ditempatkan terakhir.
```

### Konteks kategori

```js title="app.mjs"
import express from "express";
const app = express();
app.use(express.json({ limit: "16kb" }));
app.get("/health", (_req, res) => res.json({ data: { status: "ok" } }));
app.use((_req, res) => res.status(404).json({ error: { code: "NOT_FOUND" } }));
app.listen(4000, "127.0.0.1");
```

Dalam implementasi nyata, pasang error handler terakhir dan kirim pesan umum untuk status 500 sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Error Handling, verifikasi langkah “Definisikan HttpError” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
