## Overview

Queue memisahkan pekerjaan lambat dari request. Kebanyakan queue menyediakan at-least-once delivery, sehingga handler harus aman ketika job dijalankan ulang.

## Concept

Fokus penerapan **Background Jobs** adalah tentukan retry dengan backoff. Buat job idempotent. Pantau dead-letter queue. Contoh berikut memperlihatkan konteks kategori Advanced Backend; sesuaikan dengan kontrak dan batas resource aplikasi.

## Implementation

1. Tentukan retry dengan backoff.
2. Buat job idempotent.
3. Pantau dead-letter queue.

### Contoh terfokus

Periksa dependensi dan konteks pada komentar kode. Adapter seperti repository, provider, atau prisma diberikan oleh composition root; fragmen bukan server terpisah. Untuk contoh utuh, lihat [Complete Backend Starter](/docs/projects/complete-backend-starter).

```js title="background-jobs.mjs"
export async function processEmail(job, sender, processed) {
  // processed adalah adapter persisten; reserve+send memerlukan desain idempotency provider.
  if (await processed.has(job.id)) return;
  await sender.send({ ...job.payload, idempotencyKey: job.id });
  await processed.mark(job.id);
}
// Gunakan retry backoff dan dead-letter queue. Mark saja tidak menjamin exactly-once.
```

### Konteks kategori

```js title="fetch.mjs"
export async function readJSON(url) {
  const response = await fetch(url, { signal: AbortSignal.timeout(5000) });
  if (!response.ok) throw new Error(`Provider returned ${response.status}`);
  return response.json();
}
// Gunakan URL dari konfigurasi server, bukan URL bebas dari user.
```

## Code Explanation

Queue memisahkan pekerjaan lambat dari request. Kebanyakan queue menyediakan at-least-once delivery, sehingga handler harus aman ketika job dijalankan ulang. Dalam implementasi nyata, buat job idempotent dan pantau dead-letter queue sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Background Jobs, verifikasi langkah “Tentukan retry dengan backoff” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>

- Buat job idempotent.
- Batasi hak akses dan data yang dikirim ke client.
- Pantau dead-letter queue.
