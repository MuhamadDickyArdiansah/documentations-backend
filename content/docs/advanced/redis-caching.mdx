## Overview

Cache-aside membaca cache lalu database ketika miss. TTL membatasi stale data, tetapi invalidasi setelah write tetap dibutuhkan jika konsistensi lebih ketat.

## Concept

Fokus penerapan **Redis Caching** adalah gunakan key berversi. Tetapkan TTL. Hindari cache error sebagai data sukses. Contoh berikut memperlihatkan konteks kategori Advanced Backend; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.

## Implementation

1. Gunakan key berversi.
2. Tetapkan TTL.
3. Hindari cache error sebagai data sukses.

### Contoh terfokus

Periksa dependensi dan konteks pada komentar kode. Adapter seperti repository, provider, atau prisma diberikan oleh composition root; fragmen bukan server terpisah. Untuk contoh utuh, lihat [Complete Backend Starter](/docs/projects/complete-backend-starter).

```js title="redis-caching.mjs"
// Dependency: npm install redis pada project latihan terpisah.
import { createClient } from "redis";
const client = createClient({ url: process.env.REDIS_URL });
client.on("error", () => console.error("Redis unavailable"));
await client.connect();
try {
  await client.setEx("example:v1:status", 60, JSON.stringify({ ready: true }));
  const value = await client.get("example:v1:status");
  console.log(value ? JSON.parse(value) : null);
} finally { await client.close(); }
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Redis Caching, verifikasi langkah “Gunakan key berversi” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
