## Overview

Notifikasi memisahkan event domain dari saluran pengiriman. Preferensi user dan deduplication menentukan apakah event perlu dikirim lewat email, push, atau in-app.

## Concept

Fokus penerapan **Notifications** adalah simpan status delivery. Hormati preferensi user. Gunakan event ID untuk deduplication. Contoh berikut memperlihatkan konteks kategori Advanced Backend; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Implementation

1. Simpan status delivery.
2. Hormati preferensi user.
3. Gunakan event ID untuk deduplication.

### Contoh terfokus

Periksa dependensi dan konteks pada komentar kode. Adapter seperti repository, provider, atau prisma diberikan oleh composition root; fragmen bukan server terpisah. Untuk contoh utuh, lihat [Complete Backend Starter](/docs/projects/complete-backend-starter).

```js title="notifications.mjs"
export function channelsFor(preferences, event) {
  const result = ["in-app"];
  if (preferences.email && event.priority === "high") result.push("email");
  return result;
}
console.log(channelsFor({ email: false }, { priority: "high" })); // in-app
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Notifications, verifikasi langkah “Simpan status delivery” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
