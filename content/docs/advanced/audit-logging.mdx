## Overview

Audit log menjelaskan siapa melakukan apa terhadap resource dan kapan. Log audit perlu retention, kontrol akses, serta perlindungan dari perubahan atau penghapusan.

## Concept

Fokus penerapan **Audit Logging** adalah catat actor dan action. Jangan simpan secret. Gunakan storage append-only bila dibutuhkan. Contoh berikut memperlihatkan konteks kategori Advanced Backend; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Implementation

1. Catat actor dan action.
2. Jangan simpan secret.
3. Gunakan storage append-only bila dibutuhkan.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="audit-logging.mjs"
export function audit({ actorId, action, resourceId }) {
  console.log(JSON.stringify({
    at: new Date().toISOString(), actorId, action, resourceId,
  }));
}
// Production: salurkan ke storage dengan retention dan akses terbatas.
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Audit Logging, verifikasi langkah “Catat actor dan action” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
