## Overview

Idempotency key menghubungkan retry ke satu hasil operasi. Penyimpanan key dan side effect harus atomik agar dua request bersamaan tidak memproses transaksi dua kali.

## Concept

Fokus penerapan **Idempotency** adalah scope key ke actor dan endpoint. Simpan hash request. Tolak key sama dengan payload berbeda. Contoh berikut memperlihatkan konteks kategori Advanced Backend; sesuaikan dengan kontrak dan batas resource aplikasi.

## Implementation

1. Scope key ke actor dan endpoint.
2. Simpan hash request.
3. Tolak key sama dengan payload berbeda.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```sql title="idempotency.sql"
CREATE TABLE idempotency_keys (
  actor_id uuid NOT NULL,
  key text NOT NULL,
  request_hash text NOT NULL,
  response jsonb,
  PRIMARY KEY (actor_id, key)
);
-- Insert key dan efek bisnis dalam transaksi yang sama.
```

### Konteks kategori

```js title="fetch.mjs"
export async function readJSON(url) {
  const response = await fetch(url, { signal: AbortSignal.timeout(5000) });
  if (!response.ok) throw new Error(`Provider returned ${response.status}`);
  return response.json();
}
// Gunakan URL dari konfigurasi server, bukan URL bebas dari user.
```

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Idempotency, verifikasi langkah “Scope key ke actor dan endpoint” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.
