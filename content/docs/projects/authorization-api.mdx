## Overview

Project authorization menambahkan permission dan ownership setelah identitas terbukti. Uji dua user untuk memastikan satu user tidak dapat membaca data user lain.

## Concept

Fokus penerapan **Authorization API** adalah baca policy authorization. Jalankan test akses lintas user. Pisahkan role dari input request. Contoh berikut memperlihatkan konteks kategori Backend Project References; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

## Implementation

1. Baca policy authorization.
2. Jalankan test akses lintas user.
3. Pisahkan role dari input request.

### Contoh terfokus

Periksa dependensi dan konteks pada komentar kode. Adapter seperti repository, provider, atau prisma diberikan oleh composition root; fragmen bukan server terpisah. Untuk contoh utuh, lihat [Complete Backend Starter](/docs/projects/complete-backend-starter).

```js title="authorization-api.mjs"
const grants = { user: new Set(['notes:read', 'notes:write']), admin: new Set(['notes:read', 'notes:write', 'users:read']) };
export function can(actor, permission) { return !!actor && !!grants[actor.role]?.has(permission); }
export function owns(actor, resource) { return !!actor && !!resource && actor.id === resource.ownerId; }
```

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Authorization API, verifikasi langkah “Baca policy authorization” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Testing

Uji Authorization API dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “baca policy authorization” sesuai kontrak. Tambahkan test tanpa token dan test akses lintas user.

```bash title="verifikasi contoh utama"
npm run test:examples
```
