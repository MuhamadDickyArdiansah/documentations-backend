## Overview

Soft delete menyimpan deletedAt dan menyaring record aktif. Unique constraint dan restore membutuhkan desain khusus agar record yang dihapus tidak memblokir data baru secara tak sengaja.

## Concept

Fokus penerapan **Soft Delete** adalah filter deletedAt secara konsisten. Rancang partial unique index. Tetapkan retention dan proses hard delete. Contoh berikut memperlihatkan konteks kategori CRUD Operations; sesuaikan dengan kontrak dan batas resource aplikasi.

## Implementation

1. Filter deletedAt secara konsisten.
2. Rancang partial unique index.
3. Tetapkan retention dan proses hard delete.

### Contoh terfokus

Jalankan berkas .mjs ini dari root repository agar path import examples sesuai.

```sql title="soft-delete.sql"
ALTER TABLE user_notes ADD COLUMN deleted_at timestamptz;
SELECT id, title FROM user_notes
WHERE owner_id = '00000000-0000-4000-8000-000000000001'
AND deleted_at IS NULL;
```

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Soft Delete, verifikasi langkah “Filter deletedAt secara konsisten” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>

- Rancang partial unique index.
- Batasi hak akses dan data yang dikirim ke client.
- Tetapkan retention dan proses hard delete.
