## Overview

Delete harus menentukan apakah data dihapus fisik atau ditandai terhapus. Kontrak idempotency tidak berarti semua percobaan harus menghasilkan status identik.

## Concept

Fokus penerapan **Delete** adalah periksa ownership. Tentukan cascade. Return 204 tanpa JSON body. Contoh berikut memperlihatkan konteks kategori CRUD Operations; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

## Installation

Dari root repository, jalankan perintah berikut. Dependensi contoh dikelola bersama lockfile project.

```bash title="terminal"
npm ci
npm run examples
```

## Implementation

1. Periksa ownership.
2. Tentukan cascade.
3. Return 204 tanpa JSON body.

### Contoh terfokus

Jalankan berkas .mjs ini dari root repository agar path import examples sesuai.

```js title="delete.mjs"
import { createNoteRepository } from "./examples/crud/repository.mjs";
const repository = createNoteRepository();
const note = repository.create("u1", "Temporary");
console.assert(repository.delete(note.id, "u1"));
console.assert(!repository.delete(note.id, "u1"));
```

### Konteks kategori

```bash title="terminal"
curl -i -X POST http://localhost:4000/api/notes \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"Belajar backend"}'
```

## Code Explanation

Delete harus menentukan apakah data dihapus fisik atau ditandai terhapus. Kontrak idempotency tidak berarti semua percobaan harus menghasilkan status identik. Dalam implementasi nyata, tentukan cascade dan return 204 tanpa json body sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Delete, verifikasi langkah “Periksa ownership” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>

- Tentukan cascade.
- Batasi hak akses dan data yang dikirim ke client.
- Return 204 tanpa JSON body.
