## Overview

Operasi resource terkait harus memverifikasi akses ke seluruh parent dan child. Gunakan transaksi ketika beberapa write membentuk satu invariant bisnis.

## Concept

Fokus penerapan **Relational CRUD** adalah validasi parent milik actor. Batasi nested write. Rollback jika satu bagian gagal. Contoh berikut memperlihatkan konteks kategori CRUD Operations; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

## Installation

Dari root repository, jalankan perintah berikut. Dependensi contoh dikelola bersama lockfile project.

```bash title="terminal"
npm ci
npm run examples
```

## Implementation

1. Validasi parent milik actor.
2. Batasi nested write.
3. Rollback jika satu bagian gagal.

### Contoh terfokus

Periksa dependensi dan konteks pada komentar kode. Adapter seperti repository, provider, atau prisma diberikan oleh composition root; fragmen bukan server terpisah. Untuk contoh utuh, lihat [Complete Backend Starter](/docs/projects/complete-backend-starter).

```sql title="relational-crud.sql"
-- Setelah membuat users dan user_notes, jalankan dalam transaksi.
INSERT INTO user_notes (id, owner_id, title)
SELECT $1, id, $3 FROM users WHERE id = $2
RETURNING id, title;
-- Parameter $2 berasal dari actor terautentikasi, bukan body.
```

### Konteks kategori

```bash title="terminal"
curl -i -X POST http://localhost:4000/api/notes \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"Belajar backend"}'
```

## Code Explanation

Operasi resource terkait harus memverifikasi akses ke seluruh parent dan child. Gunakan transaksi ketika beberapa write membentuk satu invariant bisnis. Dalam implementasi nyata, batasi nested write dan rollback jika satu bagian gagal sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Relational CRUD, verifikasi langkah “Validasi parent milik actor” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>

- Batasi nested write.
- Batasi hak akses dan data yang dikirim ke client.
- Rollback jika satu bagian gagal.

## Testing

Uji Relational CRUD dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “validasi parent milik actor” sesuai kontrak. Tambahkan test tanpa token dan test akses lintas user.

```bash title="verifikasi contoh utama"
npm run test:examples
```
