## Overview

Authorization dijalankan di server untuk setiap aksi. Default deny lebih aman: akses diberikan hanya ketika policy cocok, bukan saat tidak ada larangan.

## Concept

Fokus penerapan **Authorization Fundamentals** adalah tentukan actor, action, resource. Pisahkan policy dari route. Uji skenario yang harus ditolak. Contoh berikut memperlihatkan konteks kategori Authorization; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

## Implementation

1. Tentukan actor, action, resource.
2. Pisahkan policy dari route.
3. Uji skenario yang harus ditolak.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="authorization-fundamentals.mjs"
export function allow(actor, action, resource) {
  if (!actor || !resource) return false;
  return action === "read" && actor.id === resource.ownerId;
}
```

### Konteks kategori

```js title="policy.mjs"
export function canUpdateNote(actor, note) {
  if (!actor || !note) return false;
  return actor.id === note.ownerId;
}
console.assert(canUpdateNote({ id: "u1" }, { ownerId: "u1" }));
console.assert(!canUpdateNote({ id: "u2" }, { ownerId: "u1" }));
```

## Code Explanation

Authorization dijalankan di server untuk setiap aksi. Default deny lebih aman: akses diberikan hanya ketika policy cocok, bukan saat tidak ada larangan. Dalam implementasi nyata, pisahkan policy dari route dan uji skenario yang harus ditolak sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Authorization Fundamentals, verifikasi langkah “Tentukan actor, action, resource” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="warn" title="Batas implementasi">Contoh adalah sarana belajar dan bukan audit keamanan. Untuk production, gunakan TLS, shared persistent storage, rate limit terdistribusi, serta pengelolaan secret yang sesuai infrastruktur.</Callout>

- Pisahkan policy dari route.
- Batasi hak akses dan data yang dikirim ke client.
- Uji skenario yang harus ditolak.

## Testing

Uji Authorization Fundamentals dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “tentukan actor, action, resource” sesuai kontrak. Tambahkan test tanpa token dan test akses lintas user.

```bash title="verifikasi contoh utama"
npm run test:examples
```
