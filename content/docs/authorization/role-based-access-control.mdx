## Overview

RBAC memetakan role ke permission lalu permission ke aksi. Jangan percaya role yang dikirim request body; ambil role dari sumber identitas yang terpercaya.

## Concept

Fokus penerapan **Role-Based Access Control** adalah definisikan role terpusat. Map role ke permission. Periksa akses sebelum side effect. Contoh berikut memperlihatkan konteks kategori Authorization; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

## Implementation

1. Definisikan role terpusat.
2. Map role ke permission.
3. Periksa akses sebelum side effect.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="role-based-access-control.mjs"
const grants = { user: ["notes:read"], editor: ["notes:read", "notes:write"] };
export const hasPermission = (actor, permission) =>
  Boolean(actor && grants[actor.role]?.includes(permission));
```

### Konteks kategori

```js title="policy.mjs"
export function canUpdateNote(actor, note) {
  if (!actor || !note) return false;
  return actor.id === note.ownerId;
}
console.assert(canUpdateNote({ id: "u1" }, { ownerId: "u1" }));
console.assert(!canUpdateNote({ id: "u2" }, { ownerId: "u1" }));
```

## Code Explanation

RBAC memetakan role ke permission lalu permission ke aksi. Jangan percaya role yang dikirim request body; ambil role dari sumber identitas yang terpercaya. Dalam implementasi nyata, map role ke permission dan periksa akses sebelum side effect sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Role-Based Access Control, verifikasi langkah “Definisikan role terpusat” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="warn" title="Batas implementasi">Contoh adalah sarana belajar dan bukan audit keamanan. Untuk production, gunakan TLS, shared persistent storage, rate limit terdistribusi, serta pengelolaan secret yang sesuai infrastruktur.</Callout>

- Map role ke permission.
- Batasi hak akses dan data yang dikirim ke client.
- Periksa akses sebelum side effect.

## Testing

Uji Role-Based Access Control dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “definisikan role terpusat” sesuai kontrak. Tambahkan test tanpa token dan test akses lintas user.

```bash title="verifikasi contoh utama"
npm run test:examples
```
