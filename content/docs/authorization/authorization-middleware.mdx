## Overview

Middleware policy menerjemahkan permission menjadi keputusan akses yang konsisten. Resource yang dibaca setelah pemeriksaan tetap perlu scope yang sama saat update.

## Concept

Fokus penerapan **Authorization Middleware** adalah buat factory requirePermission. Terima actor dari middleware terpercaya. Hindari perbedaan check dan write. Contoh berikut memperlihatkan konteks kategori Authorization; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Materi [Getting Started](/docs/getting-started) dan dasar async/await.
- Contoh API lokal pada folder examples; jalankan npm ci dari root.

## Implementation

1. Buat factory requirePermission.
2. Terima actor dari middleware terpercaya.
3. Hindari perbedaan check dan write.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="authorization-middleware.mjs"
export function requireOwner(loadResource) {
  return async (req, res, next) => {
    const resource = await loadResource(req.params.id, req.actor.id);
    if (!resource) return res.status(404).json({ error: { code: "NOT_FOUND" } });
    req.resource = resource;
    next();
  };
}
```

### Konteks kategori

```js title="policy.mjs"
export function canUpdateNote(actor, note) {
  if (!actor || !note) return false;
  return actor.id === note.ownerId;
}
console.assert(canUpdateNote({ id: "u1" }, { ownerId: "u1" }));
console.assert(!canUpdateNote({ id: "u2" }, { ownerId: "u1" }));
```

## Code Explanation

Middleware policy menerjemahkan permission menjadi keputusan akses yang konsisten. Resource yang dibaca setelah pemeriksaan tetap perlu scope yang sama saat update. Dalam implementasi nyata, terima actor dari middleware terpercaya dan hindari perbedaan check dan write sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Authorization Middleware, verifikasi langkah “Buat factory requirePermission” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="warn" title="Batas implementasi">Contoh adalah sarana belajar dan bukan audit keamanan. Untuk production, gunakan TLS, shared persistent storage, rate limit terdistribusi, serta pengelolaan secret yang sesuai infrastruktur.</Callout>

- Terima actor dari middleware terpercaya.
- Batasi hak akses dan data yang dikirim ke client.
- Hindari perbedaan check dan write.

## Testing

Uji Authorization Middleware dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “buat factory requirepermission” sesuai kontrak. Tambahkan test tanpa token dan test akses lintas user.

```bash title="verifikasi contoh utama"
npm run test:examples
```
