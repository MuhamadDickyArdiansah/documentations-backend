## Overview

Izin terhadap jenis resource belum menjamin izin terhadap record tertentu. Selalu periksa ownerId atau tenantId untuk mencegah broken object level authorization.

## Concept

Fokus penerapan **Resource Ownership** adalah tambahkan ownerId dalam query. Jangan mengandalkan ID yang sulit ditebak. Uji akses lintas pengguna. Contoh berikut memperlihatkan konteks kategori Authorization; sesuaikan dengan kontrak dan batas resource aplikasi.

## Implementation

1. Tambahkan ownerId dalam query.
2. Jangan mengandalkan ID yang sulit ditebak.
3. Uji akses lintas pengguna.

### Contoh terfokus

Cuplikan ini berfokus pada konsep di atas. Untuk fragmen middleware, daftarkan pada aplikasi Express setelah dependensi yang dibutuhkan; contoh aplikasi lengkap tersedia pada Project References.

```js title="resource-ownership.mjs"
export function visibleTo(actor, rows) {
  if (!actor) return [];
  return rows.filter(row => row.ownerId === actor.id);
}
// Di SQL: WHERE id = $1 AND owner_id = $2
```

### Konteks kategori

```js title="policy.mjs"
export function canUpdateNote(actor, note) {
  if (!actor || !note) return false;
  return actor.id === note.ownerId;
}
console.assert(canUpdateNote({ id: "u1" }, { ownerId: "u1" }));
console.assert(!canUpdateNote({ id: "u2" }, { ownerId: "u1" }));
```

## Code Explanation

Izin terhadap jenis resource belum menjamin izin terhadap record tertentu. Selalu periksa ownerId atau tenantId untuk mencegah broken object level authorization. Dalam implementasi nyata, jangan mengandalkan id yang sulit ditebak dan uji akses lintas pengguna sebelum meneruskan hasil ke bagian aplikasi berikutnya.

## API Examples

Contoh API lokal menggunakan resource notes. Endpoint mutasi membutuhkan bearer access token hasil login.

| Method | Endpoint | Authentication | Hasil |
| --- | --- | --- | --- |
| GET | /health | Tidak | 200, status proses |
| POST | /api/auth/login | Tidak | 200, pasangan token |
| GET | /api/notes | Bearer token | 200, daftar milik actor |
| POST | /api/notes | Bearer token | 201, note baru |

```json title="POST /api/notes — request"
{"title":"Belajar backend"}
```

```json title="201 — response shape"
{"data":{"id":"<note-id>","ownerId":"<user-id>","title":"Belajar backend"}}
```

Kirim header Content-Type: application/json. Token dan ID pada response merupakan placeholder; gunakan nilai dari server lokal. Lihat [Complete Backend Starter](/docs/projects/complete-backend-starter) untuk alur lengkap.

## Error Handling

Gunakan 401 untuk credential tidak valid, 404 untuk record yang tidak tersedia dalam scope actor, 409 untuk konflik, dan 422 untuk body yang tidak memenuhi schema. Response error berbentuk object error dengan code dan message. Untuk Resource Ownership, verifikasi langkah “Tambahkan ownerId dalam query” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="warn" title="Batas implementasi">Contoh adalah sarana belajar dan bukan audit keamanan. Untuk production, gunakan TLS, shared persistent storage, rate limit terdistribusi, serta pengelolaan secret yang sesuai infrastruktur.</Callout>

- Jangan mengandalkan ID yang sulit ditebak.
- Batasi hak akses dan data yang dikirim ke client.
- Uji akses lintas pengguna.
