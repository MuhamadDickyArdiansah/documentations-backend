## Overview

Lingkungan pengembangan yang konsisten mengurangi perbedaan perilaku antar komputer. Simpan versi runtime, lockfile, dan konfigurasi editor bersama project.

## Concept

Fokus penerapan **Development Environment** adalah pasang Node.js dan Git. Aktifkan format saat menyimpan. Pisahkan konfigurasi lokal dari secret production. Contoh berikut memperlihatkan konteks kategori Getting Started; sesuaikan dengan kontrak dan batas resource aplikasi.

## Prerequisites

- Node.js LTS yang masih didukung, npm, dan terminal.
- Pemahaman dasar fungsi JavaScript dan object JSON.
- Folder latihan terpisah agar perubahan tidak memengaruhi data production.

## Installation

Contoh kategori ini memakai Node.js atau tools yang disebut pada contoh. Untuk berkas .mjs, jalankan node diikuti nama file.

## Project Structure

Simpan latihan Development Environment pada module fitur terkait. Pisahkan transport HTTP, aturan bisnis, dan akses data agar dapat diuji secara mandiri.

```text title="struktur referensi"
src/
  features/
    notes/
      notes.routes.mjs
      notes.service.mjs
      notes.repository.mjs
  app.mjs
  server.mjs
```

## Implementation

1. Pasang Node.js dan Git.
2. Aktifkan format saat menyimpan.
3. Pisahkan konfigurasi lokal dari secret production.

### Contoh terfokus

Periksa dependensi dan konteks pada komentar kode. Adapter seperti repository, provider, atau prisma diberikan oleh composition root; fragmen bukan server terpisah. Untuk contoh utuh, lihat [Complete Backend Starter](/docs/projects/complete-backend-starter).

```bash title="development-environment.bash"
node --version
npm --version
git --version
# Jalankan dari repository:
npm ci
npm run dev
```

### Konteks kategori

```bash title="terminal"
node --version
npm --version
npm init -y
npm install express
```

## API Examples

Topik ini merupakan konsep internal, sehingga tidak mendefinisikan endpoint tersendiri. Gunakan [Basic Express API](/docs/projects/basic-express-api) untuk mempelajari cara menerapkannya pada request HTTP.

## Error Handling

Buat kegagalan terlihat pada batas module. Tangani input salah secara eksplisit dan pertahankan informasi penyebab pada log internal. Untuk Development Environment, verifikasi langkah “Pasang Node.js dan Git” ketika hasil tidak sesuai harapan. Jangan mengembalikan secret atau stack trace ke client.

## Security & Best Practices

<Callout type="info" title="Batas implementasi">Contoh ringkas memperlihatkan konsep dan perlu disesuaikan dengan validasi, authorization, serta observability aplikasi.</Callout>

- Aktifkan format saat menyimpan.
- Batasi hak akses dan data yang dikirim ke client.
- Pisahkan konfigurasi lokal dari secret production.

## Testing

Uji Development Environment dengan input valid, input kosong, dan kegagalan dependensi. Pastikan perilaku “pasang node.js dan git” sesuai kontrak. 

